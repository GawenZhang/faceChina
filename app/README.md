# OxyHealth website reconstruction

Responsive React/Vite reconstruction with 70 generated static pages. All 61 non-homepage URLs in the root `ACCEPTANCE-CHECKLIST.md` are included. Build with `npm.cmd run build` on Windows or `npm run build` elsewhere. Serve the contents of `dist/` from a static host.

Implemented: the preserved homepage scroll scenes, desktop/mobile navigation, five full product details, fifteen full article details (including the seven required articles), seven independent pages, 29 SEO pages including a filterable research library, three comparisons, five legal documents, and a working pressure/oxygen conversion tool. Product cards, article cards, navigation and footer use ordinary full-document links. Existing inquiry/video dialogs, FAQ disclosures, event galleries and downloads remain available. Longer prose is rewritten or uses the authorized placeholders.

`route-manifest.mjs` is the shared route registry. The build fails if any checklist URL is missing or registered twice, and generates an `index.html` for each address with its page title. `navigation-data.mjs` maps labels explicitly to their original destinations. Unknown paths show a not-found view; static hosts should use the generated `404.html` for unavailable addresses.

Original image and logo URLs are referenced from oxyhealth.com. Inter is loaded from the Fontsource CDN; these assets need a network connection. React, ReactDOM and Scheduler are bundled locally under their MIT license in `vendor/`. Brand and photography belong to their respective owners; this is a local reconstruction, not an official published site.

Inquiry and chat interfaces explicitly indicate that messages are not sent. No backend or external publishing is configured.

Run `npm run qa` after building to run all twelve Playwright QA scripts, including `qa-navigation.mjs`; per-script exit codes and output are saved in `qa-suite-results.json`. The navigation regression reads the actual root acceptance checklist, audits all generated pages, clicks every checklist destination and each ATA product name at desktop/phone widths, and checks new-document navigation, refresh and Back. It also checks explicit original destinations for financing, event registrations, social links and footer resources; external-page responses are stubbed. Legitimate section links and video/inquiry controls are distinguished from page-entry placeholders. Other scripts cover representative templates, responsive layout, conversion formulas, filters, forms, FAQs, downloads, menus, the ATA gauge and dialog keyboard behavior. Offline media placeholders do not certify original visual parity. Live navigation progress is available in `qa-navigation-progress.json`.

Craft Anything `rebuild_check` checks its previously captured five pages and states; it does not automatically compare all newly added pages. See `ACCEPTANCE-REPORT.md`, `verification.json`, and the latest audit records under `inspection/` and `evidence-extended-current/` for verification results and remaining reference gaps. The new route-arrival motion retains full-document links and reduced-motion support. Its 600 ms duration and easing remain provisional because original script/animation capture is unavailable; homepage scroll interpolation is unchanged.

`verification-run.json` records the scope of the current local verification: zero original-source browser calls, any current UI changes, and whether the full QA suite was rerun or retained from an earlier run. Its QA completion time and artifact hashes must match the actual QA/build records before the reports can be generated. Refreshing a report date does not imply another source-browser call or QA run occurred.

Background regression: `qa-backgrounds.mjs` inventories 70 routes at 1440/768/390, checks all five product section surfaces and text polarity, light-guide CTA contrast, and recorded source backgrounds for the five original captures. Precise source sequences for the other templates remain unverified because original HTML/CSS/render retrieval is blocked. See `ACCEPTANCE-REPORT.md`.

Historical original-site attempts are preserved in `live-source-session.json` (approximately 12:18 UTC on 2026-11-12) and the earlier `live-source-retry.json`. Each records one attempted `web_site_open` call for `/why-oxyhealth`, rejected before execution, with the other 43 target URLs unrequested. They are historical logs, not the current run's activity. All 44 target background, exact color and visual layout comparisons remain unverified, including 11 provisional page structures. `live-source-audit.json` combines current local-run scope with those historical logs and the older 33 readable / 11 unavailable text results. The four original per-family source records remain unchanged.

Earlier model-list and research/guide structure fixes, provisional-page markers, accepted colors and placeholder media are retained.
